# Meerschaum Documentation Style & Standards

Meerschaum's documentation (`meerschaum.io`, built from `docs/zensical/` with Zensical) should feel like the original v3 docs: **brief, practical, approachable, and easy to navigate**. Write for a user trying to get a pipeline working — not as an internal architecture spec or legal disclaimer.

## Core Principles

1. **Brevity over exhaustiveness.** Keep paragraphs to **1–3 sentences** (never 100+ word unbroken blocks). If a sentence only restates an internal implementation detail or obvious edge case, delete it.
2. **Show, don't narrate.** Lead with what the feature does and a **short, copy-pasteable CLI, Python, or YAML example**. Use compact Markdown tables for flags, config keys, roles, and APIs instead of prose lists.
3. **One canonical home per topic.** Explain a subsystem once on its main reference page and link to it from everywhere else. Never copy-paste security, sandbox, stack, or engine explanations across 3–5 pages.
4. **Hide deep internals.** Low-level mechanics (e.g., Landlock ABI numbers, manual `pg_dump` fallbacks, long config dumps) belong in a collapsible `<details markdown="1">` or a short `??? note` admonition — never blocking the main flow.
5. **Keep navigation tight.** Prefer cohesive pages over 6–7 tiny 200-word micro-pages. Every Markdown file under `docs/zensical/` should be in `docs/zensical.toml` `nav` (no orphans) and cross-page links must match real headings.
6. **Public-safe examples only.** Never reference private deployments, organizations, personal hostnames, or secrets in docs or fixtures.

## Page Word-Count Budgets (Soft Targets)

| Page type | Target length |
|---|---:|
| Get Started / tutorial step | 250–450 words |
| Standard reference page | 800–1,800 words |
| Major reference hub (Pipes, Pipelines, Migration) | 1,500–2,500 words |
| Patch release changelog (`x.y.z`) | 250–500 words |
| Minor release changelog (`x.y.0`) | 800–1,500 words |

If a page grows past ~2,500 words, ask whether you are duplicating another page, narrating every UI button/flag in prose, or documenting internal implementation details instead of user workflows.

## Changelog & Release Notes (`docs/zensical/changelog/v5.md`)

- **Source of truth:** Edit `docs/zensical/changelog/v5.md` only; never hand-edit root `CHANGELOG.md` (generated by `scripts/generate_changelog.py`).
- **Format:** Match the crisp bullet style:
  ```markdown
  - **Short bold summary ending with a period.**  
    One or two concise sentences explaining what changed and why it matters. Link to the reference page for deep details.

    ```bash
    mrsm sync pipes --schedule "daily starting 21:00 tz America/New_York"
    ```
  ```
- **Upgrade notes first:** Put required user actions in a short `### Before upgrading` bullet list at the top of the release.
- **No RC noise:** Do not dump internal release-candidate bugfixes or micro-refactorings into final release notes.
- **Collapse older series:** Group previous minor series under `<details markdown="1"><summary>Read 5.0.x release notes</summary>...</details>`.
- **GitHub Releases & PR bodies:** Reuse the version's changelog section verbatim (promoting `## X.Y.Z` to `# X.Y.Z`).

## Asciinema Embeds

Asciinema v3 is bundled locally (`docs/zensical/assets/vendor/asciinema-player.*`) and mounted by `docs/zensical/assets/js/media.js`.

- **Supported attributes on `<asciinema-player>`:** `src`, `title`, `autoplay`, `loop`, `preload`, `rows`, `cols`, `speed`, `idle-time-limit`, `poster`, `fit`, `theme`.
- **Home page only autoplays:** `docs/zensical/index.md` uses `autoplay="true" loop="true" preload="true" rows="18" idle-time-limit="2" poster="npt:0:04"`. Other pages should omit `autoplay` and include `rows="..." idle-time-limit="2" poster="npt:0:04"` so they render a crisp preview frame without distracting the reader.
- **Do not use** legacy v2 `size="small"` attributes or defensive captions like `"Genuine CLI recording from 5.0.0rc16..."`.
- `media.js` automatically respects `prefers-reduced-motion`, pauses/resumes on scroll, mounts cleanly inside collapsible `<details>`, and disposes players on Zensical instant navigation.

## Generated & Test-Checked Pages

- **`docs/zensical/reference/mcp/tools.md`** is generated from `crates/meerschaum-server/src/mcp/docs.rs` (`python3 scripts/generate_mcp_docs.py`) and verified by `cargo test -p meerschaum-server --test mcp_suite -- mcp_docs::`. Do not hand-edit it.
- **`docs/zensical/reference/api-instance/permissions.md`** contains a `<!-- non-admin-commands:start --> ... <!-- non-admin-commands:end -->` block verified by `crates/meerschaum-server/tests/routes_access_suite/access_matrix/commands.rs`. Keep that block unchanged when editing surrounding prose.

## Required Verification Before Committing Docs Changes

```bash
python3 scripts/generate_changelog.py      # whenever docs/zensical/changelog/ changes
python3 scripts/gen_llms_txt.py            # REQUIRED: CI checks git diff on llms.txt & llms-full.txt
./scripts/docs.sh --site-only              # runs `zensical build --strict` (catches broken links/anchors)
```

Remember to commit any updated `CHANGELOG.md`, `docs/zensical/llms.txt`, and `docs/zensical/llms-full.txt` alongside your edits.
