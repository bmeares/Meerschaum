# Meerschaum v5.0.0rc7 usability addendum

Date: 2026-10-22

This addendum records the requested fixes and Astra's review of the Pipelines page.
It extends the [rc6 specification](v5.0.0rc6.md).

- History links preserve the Pipeline registry, name, and requested run through dropdown
  hydration, refresh, and polling. Selecting a different Pipeline clears the previous run.
- Run now explicitly selects its new run and opens command output directly on the canvas,
  including the mobile Output pane. Logs identify the Pipeline, run ID, and worker status.
  View output reopens retained output; closing the drawer does not stop the execution.
- Pipe output and whole-Pipeline output are separate, explicitly attributed display modes.
  Both preserve ANSI colors and follow new lines until the user scrolls upward.
- Manage is beside the Pipeline selector. Deletion requires confirmation naming the Pipeline
  and registry, validates the confirmed identity and revision, preserves member Pipes, data,
  and history, and refuses definitions referenced by scheduled Jobs. Success clears selection
  and live output. Canceling confirmation changes nothing.
- A live worker's status may override only its own run, never another selected historical run.
- Empty history, unavailable run IDs, and runs belonging to another Pipeline have distinct
  explanations and a return to recent runs action.

Acceptance coverage includes desktop and mobile Run now, output close/reopen, deep-linked
history hydration/reload, a second execution after viewing history, and canceled/confirmed
Pipeline deletion. Existing console, CLI, cancellation, packaging, and Docker checks remain
release gates.
