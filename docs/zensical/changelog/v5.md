# Meerschaum 5

## 5.0.0 (Unreleased)

The data engine, database connectors, CLI, HTTP API, jobs, and Compose now run in Rust. Keep your Pipe definitions, configuration, Python plugins, and existing data. Start with the [migration guide](../reference/migrating-to-v5.md).

### Pipelines that know the dependencies

Save a group of Pipes, preview its plan, then run parents before children. The engine records run history, retries failures, and tracks late data for backfills.

```bash
mrsm register pipelines daily -i sql:local -c sql:local -m daily --parents
mrsm plan pipelines daily -i sql:local
mrsm sync pipelines daily -i sql:local
mrsm show runs -i sql:local
```

See [Pipelines](../reference/pipelines/index.md) for selection, schedules, and recovery.

### A fuller web console

Overview, Pipes, Pipelines, Runs, and Jobs put current work and history in one place. Performance charts show sync duration, failures, and rows affected. Inspect plugin source without running it, and manage roles, teams, access, and locks.

Pipelines have a searchable, sortable runbook with member details and recent runs loaded on demand. The canvas keeps View options in a compact popup and supports pinch zoom on phones.

```bash
python -m pip install 'meerschaum[dash]'
mrsm start api -i sql:local
```

Open `/dash`. A new server offers a first administrator account. See the [console guide](../reference/api-instance/web-console.md).

### Python stays familiar

`Pipe.sync()` still unpacks into `(success, message)`. Its `SyncResult` also provides row counts, duration, and changed intervals. Read plain dictionaries with the base package, or install a DataFrame extra.

```python
import meerschaum as mrsm

pipe = mrsm.Pipe('plugin:manual', 'readings', instance='sql:local', columns={'id': 'id'})
result = pipe.sync([{'id': 1, 'temperature': 21.5}])
print(result.success, result.inserted, result.duration)
print(pipe.get_data(as_docs=True))
```

New roots use Polars; existing roots keep pandas. [Choose the DataFrame library](../reference/pipes/reading.md#dataframe-library) explicitly when upgrading.

### Teams, permissions, and locks

Viewer, Editor, and Operator roles provide starting permissions. Teams control shared Pipe and Job access. Tokens stay within their owner's current permissions, and revocations take effect on subsequent requests. Pipe locks protect operations across the CLI, Python, jobs, HTTP, MCP, and the console.

Self-registration closes after the first administrator unless configured otherwise. Editors no longer receive unrestricted action or terminal access. Review [access and locks](../reference/pipes/access-and-locks.md) and [API permissions](../reference/api-instance/permissions.md).

### Reliable syncs and operations

- Replace an authoritative time window with `pipe.sync(rows, begin=..., end=..., replace=True)`.
- Persist numeric sync metrics across processes, with current access checks before aggregation.
- Save run events before marking completion, keeping `mrsm watch run` output complete.
- Keep private history private when a Pipe or Pipeline is deleted, recreated, or its access changes.
- Bound SQL parent reads before window functions, keeping incremental syncs fast.
- Use 30-day TimescaleDB metrics partitions and correct undersized RC partitions.
- Initialize internal tables and indexes safely when workers start together.
- Keep redirects fast on consoles with many plugin pages.
- Isolate Python hosts when API and MCP servers share a configuration root.
- Publish complete Job properties atomically, keeping listings consistent during updates.
- Release a Pipe lease even when acquisition completes after cancellation.
- Back up, restore, and upgrade Stack PostgreSQL through guided commands.

See [Stack upgrades](../reference/stack/upgrades.md) and [sync metrics](../reference/api-instance/sync-metrics.md).

### Rust plugins and applications

A plugin can be one `.rs` file, or a crate using the native SDK. Applications can embed the Pipe and engine APIs without compiling the CLI. The [developer guides](../docs/index.md) cover both Python and Rust.

### Before upgrading

Check the [migration checklist](../reference/migrating-to-v5.md) for supported platforms, optional dependencies, DataFrame defaults, permissions, API behavior, and installation ownership. Keep a backup of configuration and your database before changing a deployed installation.
