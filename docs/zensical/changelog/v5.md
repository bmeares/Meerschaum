# Meerschaum 5

## 5.1.2

Maintenance release: leaner Docker images that share layers, stricter SQL checks for non-administrators, and console, web terminal and sync fixes.

### Before upgrading from 5.1.1

- **Non-administrator SQL is checked more strictly.** Through the API and MCP, a query or pipe definition from a caller who is not an administrator is now refused when any SQL dialect would read it as more than one statement or as a write: a `;` inside a dollar-quoted string (`$$a;b$$`), or a mutating keyword after `#` or after `--` with no space. Administrators and local `mrsm` commands are unaffected.
- **Docker images run as UID and GID 1000.** This was already the default; images built by the release workflow no longer inherit the build host's IDs.

### Highlights & Fixes

- **Smaller downloads when updating Docker images.**  
  The `full`, `rust-full`, `slim` and `rust` images now share their common layers (the `mrsm` binary, the Python wheel, the plugin compiler), and operating-system layers stay identical between patch releases, so `docker pull` fetches only what changed.

- **Smaller `mrsm` binary.**  
  Release binaries and wheels are stripped of symbols and no longer build unused Arrow and Polars features. A panic backtrace keeps its message and location; stack frames show addresses instead of function names.

- **Internal tables stay unreachable through SQL comments.**  
  The API and MCP SQL checks read a query the way each database flavor does, so a table name hidden behind `#`, `--` or a nested `/* */` comment is refused on every flavor.

- **Console requests to the API ignore proxies and redirects.**  
  The Dash console's calls to its own API server no longer honor `HTTP_PROXY` or follow redirects, so a session's credentials are only ever sent to that server.

- **Job logs keep streaming past the session token's lifetime.**  
  A log stream opened in the console renews its authorization while it runs, and ends when the session's credential is rotated or revoked.

- **Web terminal fixes.**  
  A refused new window no longer blocks later ones, panes on API-only hosts get `TERM`, and a closed session tells the browser to stop instead of reconnecting.

- **The Users page follows the acting team.**  
  An administrator viewing the console as a team sees and manages that team's users only; switch back to `Everyone` to manage all users.

- **One console permission check.**  
  An isolated team member's permissions are computed in one place, so the result no longer depends on which console page loaded first.

- **In-place syncs stay on the pipe's instance.**  
  A pipe whose source is the engine's home database but whose instance is another database no longer runs its sync inside the source database.

- **Dropped engine metrics are reported.**  
  A sync metric that cannot be written within its time budget now logs a warning (at most once a minute) instead of disappearing, and Oracle instances no longer lose their internal tables' ready state after index DDL.

- **For contributors.**  
  Rust integration tests build as 45 suite binaries instead of 411, `scripts/check_architecture.py` enforces crate layering and test wiring in CI, and `GLOSSARY.md`, `docs/adr/` and `CODING_STANDARDS.md` describe the codebase's terms, decisions and review rules.

## 5.1.1

Maintenance release with console UX improvements, credential handling fixes in `stack.yaml`, and Docker stack / isolated-team fixes.

### Before upgrading from 5.1.0

- **Docker stacks:** run `mrsm stack up -d` after upgrading so `api` mounts the public executor directory at `/run/meerschaum/executors/desired` instead of `/meerschaum/executors/desired`. Any root-owned `/meerschaum/executors` placeholder left by 5.1.0 is automatically moved aside to `.executors.root-owned-<n>`.
- **Clean up expanded `stack.yaml` secrets:** if an earlier `mrsm edit config stack` or `write_config()` expanded credentials into `stack.yaml`, replace them with `MRSM{...}` references (e.g. `MRSM{!meerschaum:connectors:sql:main}` or `<DOLLAR>POSTGRES_PASSWORD`).

### Highlights & Fixes

- **Team switcher in the web console.**  
  Administrators and multi-team members now have a **Team** dropdown next to **Instance** to view the console as a specific team (or `Everyone`). Instances, pipes, connectors, plugins, and jobs narrow to that team's view without ever escalating permissions; Actions and the web terminal pause until returning to **All teams**.

- **Nested Pages menu.**  
  Plugin page groups with multiple pages now collapse into sections with page counts (groups with >3 pages start collapsed unless active), drop repeated prefixes, nest sub-paths, and filter by the viewer's allowed plugins.

- **Balanced Overview without Pipelines.**  
  The Overview page keeps Pipes and Connectors balanced across the layout when no Pipelines or syncs exist yet.

- **Preserve `MRSM{...}` references in `stack.yaml`.**  
  Generating `stack.yaml` no longer expands references inside lists (`ports`, healthchecks, Grafana data sources), and `write_config({'stack': get_config('stack')})` preserves `MRSM{!meerschaum}`, `MRSM{!system}`, and `MRSM{!api}` instead of writing plaintext secrets.

- **Externalize secrets for custom API services.**  
  Any Compose service with `MRSM_CONFIG` or `MRSM_PATCH` (such as `api-sra` alongside `api`) now writes secrets to `stack/secrets/<service>/` via `MRSM_CONFIG_FILE` / `MRSM_PATCH_FILE` on 5.1+ images, and cleans up files when a service is removed.

- **Fix `/jobs` HTTP 503 on upgraded 5.1.0 Docker stacks.**  
  Moved the host executor mount from `/meerschaum/executors/desired` to `/run/meerschaum/executors/desired` (`MRSM_EXECUTOR_DESIRED_DIR`), pre-created `/meerschaum/executors` as UID 1000 in all images, and auto-repaired empty root-owned placeholders on startup.

- **Protect team-reserved connectors from host `MRSM_CONFIG`.**  
  Connectors reserved for a team (`teams: [...]`) in an API instance's config are no longer overwritten by same-named host connectors passed through `MRSM_CONFIG` (`MRSM_PATCH` still overrides). **New team** also verifies config writability before creating a database.

- **Fix isolated-team instance fallback and policy warnings.**  
  When `api:permissions:instances` blocks an isolated team's default instance, console pages keep that instance and show one clear alert naming `allow_multiple_instances` / `allowed_instance_keys` instead of falling back to `sql:main`. Creating or editing a team with a blocked instance warns immediately.

- **Propagate Compose `profiles` to `grafana_readonly`.**  
  `grafana_readonly` inherits `profiles` from `db` and `grafana` (with `required: false` on `grafana`'s dependency when profiles differ), and `mrsm doctor` treats a completed exit-0 `grafana_readonly` container as healthy.

## 5.1.0

Security release introducing isolated team execution, read-only Grafana and file-based stack secrets, native Rust plugin SQL/transaction helpers, and immutable sync strategies. See [Teams on One Instance](../reference/api-instance/teams.md) and [Team Execution Environments](../reference/team-executors.md).

### Before upgrading from 5.0.x

- Upgrade the CLI, API host, and Python `meerschaum` package in Team worker interpreters together (5.1.0+ required). On a 5.0.x `--user` install, upgrade with `python3 -m pip install --user --upgrade meerschaum`.
- Review `stack:grafana:readonly_schemas` if dashboards read schemas outside `sql:main`'s owner, then run `mrsm stack up -d` to apply the read-only Grafana role, Valkey password, and secret files.
- Isolated Team commands/terminals require Linux 6.12+ (Landlock ABI 6) and TCP connectors (Unix sockets are denied).

### Highlights

- **Isolated teams, per-team databases, and Grafana orgs.**  
  Create isolated teams with their own PostgreSQL database/schema, roles, connectors, plugin allowlists, and auto-provisioned Grafana orgs via the console or `mrsm bootstrap teams`.

  ```bash
  mrsm bootstrap teams
  ```

- **Sandboxed team execution & optional remote executors (Linux).**  
  Isolated team plugins, jobs, and terminals run with team-only configs, allowlisted environments, per-team venvs, and Landlock + seccomp isolation (`system.engine.python_team_sandbox: auto | require | require_sockets | off`) with optional CPU/memory/disk/egress caps. Administrators can also assign a team to a generated Stack executor or standalone native executor. See [Teams](../reference/api-instance/teams.md) and [Team Execution Environments](../reference/team-executors.md).

- **Restricted non-admin actions & web terminals.**  
  Non-administrators can only execute allowed Meerschaum actions through `/execute`, `/jobs`, MCP, and the web terminal (no arbitrary host shell escapes). See [Permissions](../reference/api-instance/permissions.md).

- **Secrets in files & hardened stack defaults.**  
  Reference secrets dynamically with `MRSM{file:<path>}` and `MRSM{env:<NAME>}`, and pass patches via `MRSM_CONFIG_FILE` / `MRSM_PATCH_FILE`. `mrsm stack` moves API, Grafana, and Valkey credentials out of `docker-compose.yaml` into owner-only files under `<root>/stack/secrets/`, sets a Valkey `requirepass`, and switches Grafana's **Meerschaum Main** data source to a read-only `mrsm__main_ro` role. See [Stack](../reference/stack/index.md) and [Environment](../reference/environment.md).

  ```yaml
  connectors:
    sql:
      main:
        password: MRSM{file:/run/secrets/pg_password}
  ```

- **Immutable sync strategies.**  
  Mark append-only/immutable pipes with `sync.immutable: true` and choose a strategy (`join`, `unbounded-simple`, or monthly corrective). See [Syncing](../reference/pipes/syncing.md#immutable-synchronization-strategies).

- **Native Rust plugin SDK additions (ABI v1 compatible).**  
  Added parameterized SQL (`host::read_sql_with` / `exec_sql_with` with `:name` and native Postgres array binds), host-managed SQL transactions (`host::transaction`), `host::root_dir()`, `Pipe::id()` / `Pipe::is_registered()`, and `#[method]` custom connector methods callable from Python.

- **Time zones in schedules.**  
  Schedules now accept `tz <zone>` (`local`, `utc`, or IANA name) and restore 4.x timezone abbreviations (`EST`/`EDT`, `UTC`) with clean DST handling:

  ```bash
  mrsm sync pipes --schedule "daily starting 21:00 tz America/New_York jitter 5 minutes"
  ```

- **Engine hypertables use 7-day chunks and compression.**  
  Internal engine tables (`mrsm_engine_*`) now default to 7-day chunks, 7-day TimescaleDB compression, and `drop_chunks` retention so expired history reclaims disk space immediately.

- **Faster shell startup & incremental plugin manifests.**  
  Interactive shells and web terminals open immediately from cached manifests and refresh in the background, with per-`MRSM_PLUGINS_DIR` cache keys.

- **Connect an agent from the Tokens page.**  
  The Tokens page generates copy-pasteable MCP configuration for Claude Code, Claude Desktop, Codex, OpenCode, and other clients with the new token's API key filled in.

### Fixes & Improvements

- **PostgreSQL / SQL sync fixes.**  
  Added [`upsert_changed_only`](../reference/pipes/parameters.md#upsert_changed_only) to skip rewriting unchanged rows; fixed PostgreSQL array/enum/extension upserts, in-place syncs without PostGIS, NULL-safe comparisons for non-numeric types, and in-place partitioned/hypertable upserts.
- **Python list SQL parameter binds.**  
  Lists passed to `conn.read(query, params={'ids': [1, 2, 3]})` bind as native PostgreSQL arrays (`= ANY(:ids)`) again rather than `jsonb` (pass `json.dumps(...)` for JSON columns).
- **Safer, clearer `upgrade meerschaum`.**  
  Prompts upfront before downloading, respects `--user` / venv / PEP 668 install locations instead of overwriting system site-packages, and warns about shadowed installs.
- **Jobs, prompts, and connection diagnostics.**  
  Restored interactive `attach job` prompts, in-process `retry_connect()` without leaking passwords in process args, clearer `test_connection(warn=True)` errors, and empty `jobs: {}` in Compose.
- **Helper subprocess sanitization.**  
  Editors, SQL clients, `pip`/`uv`, `cargo`, and `systemctl` no longer inherit `MRSM_CONFIG`, `MRSM_PATCH`, or `MRSM_<TYPE>_<LABEL>` secrets.

### 5.0.2

- **Performance page selection stability.** Late refresh responses no longer reset the selected window or page.
- **DuckDB download retries.** First-time DuckDB downloads retry twice on transient HTTP/network failures.
- **Public Dash callback warnings.** Startup warns when a `@web_page(login_required=False)` plugin registers callbacks without `public=True`.
- **Dependency updates.** Updated Arrow to 60.1 (`RUSTSEC-2026-0442`) and refreshed Rust dependencies.

### 5.0.1

- **Restart `--restart` jobs on API startup.** Stopped `--restart` jobs resume automatically when the API starts (manually stopped jobs stay stopped).
- **v4 job command compatibility.** Safely reads commands stored in v4 `pickle.pkl` metadata as data without executing pickle code.
- **Security updates.** Updated `rustls-webpki`, `webpki-roots`, `zstd`, `ctutils`, and raised `PyJWT>=2.15.0` for API/Dash extras.

### 5.0.0

Meerschaum 5 rewrites the core engine, SQL/API/Valkey connectors, CLI, HTTP API, job supervisor, and Compose in Rust while keeping your Pipe definitions, configuration, Python plugins, and existing data compatible. See the [migration guide](../reference/migrating-to-v5.md).

- **Dependency-aware Pipelines.**  
  Register, preview, and run parent-before-child DAGs with run history, retries, late-data backfills, and Compose `pipelines:` support. See [Pipelines](../reference/pipelines/index.md).

  ```bash
  mrsm register pipelines daily -i sql:local -c sql:local -m daily --parents
  mrsm plan pipelines daily -i sql:local
  mrsm sync pipelines daily -i sql:local
  mrsm show runs -i sql:local
  ```

- **Expanded Web Console & Grafana dashboards.**  
  Added Overview, Pipelines canvas/runbook, Runs Gantt timeline, Engine performance charts, in-browser plugin editor, token/team/lock management, tmux-tabbed web terminal, and rebuilt **Syncs** + **Engine** Grafana dashboards. See [Web Console](../reference/api-instance/web-console.md).

- **Familiar Python API with Polars default.**  
  `Pipe.sync()` still unpacks to `(success, message)` while exposing `.inserted`, `.updated`, and `.duration` on `SyncResult`. Base installs have zero heavy dependencies (`get_data(as_docs=True)`); new roots default to Polars while existing roots keep pandas.

  ```python
  import meerschaum as mrsm

  pipe = mrsm.Pipe('plugin:manual', 'readings', instance='sql:local', columns={'id': 'id'})
  result = pipe.sync([{'id': 1, 'temperature': 21.5}])
  print(result.success, result.inserted, result.duration)
  print(pipe.get_data(as_docs=True))
  ```

- **Teams, roles, tokens, and Pipe locks.**  
  Added Viewer/Editor/Operator roles, team-scoped access, revocable scoped tokens, and cross-process Pipe locks. Self-registration now closes after creating the first administrator.

- **Rust plugins and embeddable crates.**  
  Write single-file `.rs` or Cargo plugins with the native SDK (`meerschaum-plugin`), or embed `meerschaum-engine` directly in Rust apps. See [Rust Plugins](../reference/plugins/rust-plugins.md).

- **Faster, lower-memory syncs and guided Stack upgrades.**  
  Streamed SQL fetch chunks cut peak RAM nearly in half, column-type caching and native execution speed up small SQL syncs, API shutdown drains cleanly with `/healthcheck/ready`, and `mrsm upgrade/backup/restore postgres` guide Stack maintenance.
